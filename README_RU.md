## 🎯 Ключевая проблема: Ручной труд

До реализации этого проекта сотрудники **sdmedik** тратили десятки часов на ручное обновление цен в системе PayKeeper. Данные брались с портала [КЦТН СФР](https://ktsr.sfr.gov.ru/), где собраны категории товаров и цены по сертификатам ТРУ (Технические Средства Реабилитации) для всех 89 регионов РФ.

**Проблемы:**
*   **Огромный объем данных**: Тысячи ценовых позиций (Товар × Регион × Категория).
*   **Человеческий фактор**: Ошибки при ручном вводе приводили к критическим расхождениям в ценах.
*   **Скорость изменений**: Цены меняются часто, и ручная синхронизация не успевала за актуальными данными.

---

## ⚙️ Решение: Автоматизированный движок парсинга

Проект реализует продвинутую систему скрапинга и синхронизации, которая полностью исключает ручной труд.

### 1. Интеграция с ЕСНСИ (Коды ТРУ)
Система получает актуальные коды ТРУ из официального реестра [ЕСНСИ (Госуслуги)](https://esnsi.gosuslugi.ru/rest/ext/v1/classifiers/10616/data). Это гарантирует, что в обработку попадают только официально утвержденные коды медтехники.

### 2. Парсер СФР (Региональные цены)
Оптимизированный парсер, который обходит сайт `ktsr.sfr.gov.ru` для:
*   Извлечения категорий и конкретных товаров.
*   Привязки цен к конкретным регионам РФ.
*   Прямой синхронизации данных с платежным шлюзом **PayKeeper**.

### 3. Оптимизация "бережного" парсинга
Сайт КЦТН СФР известен своей нестабильностью и частыми отказами под нагрузкой. Наш движок был специально переработан, чтобы не "ронять" исходный ресурс:
*   **Строгий Rate Limiting**: Интеллектуальные задержки между запросами.
*   **Последовательная обработка**: Отказ от агрессивного параллелизма, который вызывает блокировки или падение сервера СФР.
*   **Сохранение состояния**: Возможность продолжить работу с места прерывания при сбое внешнего сервера.

## 🏗 Архитектура и поток данных

Проект следует паттерну **Модульный монолит** с использованием принципов **Чистой архитектуры**.

### 🔄 Поток синхронизации данных
1.  **Триггер**: Запуск по расписанию (cron) или запрос администратора.
2.  **Получение кодов**: Подключение к API ЕСНСИ для обновления справочника ТРУ.
3.  **Обход СФР**: Модуль Scraper проходит по каталогу СФР, используя оптимизированные, неагрессивные HTTP-запросы.
4.  **Трансформация**: Данные нормализуются и сопоставляются с внутренними товарами.
5.  **Интеграция**: Обновленные цены отправляются в **PayKeeper** и сохраняются в локальной **PostgreSQL**.
6.  **Кэширование**: Результаты кэшируются в **Redis** для мгновенного доступа через API.

---

## 🛠 Технологический стек
*   **Backend**: Go (Fiber framework)
*   **Scraping**: Go-Query, кастомные HTTP-клиенты с логикой повторных попыток.
*   **База данных**: PostgreSQL (GORM)
*   **Кэш**: Redis
*   **Безопасность**: Casbin (RBAC) & JWT
*   **Интеграции**: PayKeeper API, Портал СФР, API ЕСНСИ.

## 🚀 Запуск локально

1.  **Клонирование и настройка**:
    ```bash
    git clone https://github.com/Fi44er/sdmed.git && cd sdmed
    cp example.env .env
    ```
2.  **Настройка PayKeeper**: Убедитесь, что в `.env` указаны верные доступы к API PayKeeper для работы синхронизации.
3.  **Запуск**:
    ```bash
    docker-compose up -d
    ```

## ⚠️ Обработка нестабильных систем

| Сценарий | Наше решение |
| :--- | :--- |
| **Падение сайта СФР** | Стратегия экспоненциального отката (backoff). Парсер ждет восстановления сайта, не перегружая его. |
| **Изменение формата данных** | Гибкий парсинг HTML через `goquery` и валидация полученных кодов ТРУ через ЕСНСИ. |
| **Таймаут PayKeeper** | Паттерн **Unit of Work** обеспечивает согласованность данных между локальной БД и платежным шлюзом. |
| **Маппинг регионов** | Внутренняя таблица соответствий для устранения различий в названиях регионов между СФР и Госуслугами. |

## 📁 Структура проекта

*   `internal/module/scraper`: Сердце автоматизации. Логика парсинга и "дружелюбного" взаимодействия с внешними сайтами.
*   `internal/module/tru`: Логика обработки кодов ТРУ и региональных данных.
*   `internal/module/order`: Интеграция с PayKeeper для финального применения цен.
*   `pkg/process_manager`: Управление фоновыми процессами скрапинга.
